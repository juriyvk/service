# Ручная приёмка staging

Проект: wepogbvijpvyvyfzxzeo. Mini App: https://juriyvk.github.io/service/staging/ . Бот: @DVFMTESTCRM_bot. Рабочий production не используется.

Владелец разрешил использовать только собственный Telegram ID для ручной приёмки, с вымышленным отображаемым именем. Остальные записи и данные для тестовых задач/документов синтетические. Автоматические тесты не используют этот личный ID. Не присылать initData, значения Secrets или заполненный SQL регистрации.

- Владелец подтвердил, что после первоначального доступа Mini App открывает задачи и разделы CRM. Это проверяет реальный Telegram вход, legacy bridge, вызовы Edge Functions и snapshot в staging; персональная запись не считывалась агентом.
- Опубликованные HTML/JS совпадают с проверенной staging-сборкой.
- GitHub Actions для fd09e35d0a108890616b270b2bfe016741ff278c завершился успешно: тесты, TypeScript, Deno, проверка артефактов и браузерные сценарии основной/staging версий.

## Подтверждённая проверка: задачи, история, документы

1. В «Проекты» создать «Приёмка CRM», ответственный — собственный тестовый аккаунт.
2. В «Задачи» создать «Проверка задачи», выбрать этот проект и себя ответственным. В карточке добавить контрольную точку «Проверить результат» и комментарий «Тестовый комментарий».
3. Принять задачу, перевести в работу, указать 50%, отметить точку выполненной, отправить на проверку и завершить. Завершение должно показать 100%; история должна содержать изменения и комментарий.
4. Полностью закрыть Mini App и открыть заново. Задача, комментарий, точка и история должны сохраниться. Проверить фильтр завершённых и счётчики аналитики.
5. В «Документы» загрузить docs/fixtures/crm-check.txt (или собственный TXT с вымышленным содержимым), открыть файл и сверить текст. После повторного открытия приложения файл должен оставаться в библиотеке. Проверка чужого файла выполняется автоматическими тестами; не добавлять реальных сотрудников ради этого шага.

13 ноября 2026 (московское время) владелец сообщил, что весь предложенный сценарий работает: задача/контрольная точка/комментарий/история сохраняются после повторного открытия, тестовый файл загружается и открывается. Это ручное подтверждение в реальном staging; агент не считывал личную запись или содержимое частной библиотеки.

## Затем: Telegram и доставка

- Отправка текста/команды боту должна создавать задачу, отправка тестового файла — сохранять его в личной библиотеке.
- Перед проверкой уведомлений и кнопки «Открыть задачу» настроить main/named Mini App в BotFather и TELEGRAM_MINI_APP_URL. Сейчас известна только кнопка меню, и прямой startapp link ещё не подтверждён.
- Настроить scheduler для worker через защищённое хранилище секрета; он не должен зависеть от новых сообщений боту. Пока наличие scheduler не подтверждено.
- Проверить повтор update_id и недоступность Telegram без реальных персональных данных в автоматических тестах.

Управление сотрудниками через интерфейс остаётся последним этапом после приёмки ядра и серверных прав. Основной PR #1 остаётся черновиком до подтверждения deep links и уведомлений. Подготовка scheduler и порядок оставшейся проверки: docs/NOTIFICATIONS.md.
