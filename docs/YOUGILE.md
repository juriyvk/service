# YouGile: проверка подключения

Через подключение YouGile прочитаны существующий проект «Сервисное сопровождение | ДВФМ» и доска «Задачи отдела». Структура и задачи не изменялись. Режим связки ещё должен выбрать владелец: CRM как основная система, YouGile как основная система либо двусторонняя синхронизация.

Подготовлен независимый первый этап: supabase/functions/yougile/index.ts, клиент _shared/yougile.js и standalone deploy/dashboard/yougile.ts. Endpoint не развёрнут. Он принимает POST с initData и action=inspect, проверяет подпись Telegram и роль manager/deputy из БД, затем читает только выбранный проект, доску и её колонки. В ответе read_only=true, sync_enabled=false. Создание/изменение задач, импорт сотрудников и документов отсутствуют.

Серверные Secrets: YOUGILE_API_KEY, YOUGILE_PROJECT_ID, YOUGILE_BOARD_ID. Необязательный YOUGILE_API_BASE, по умолчанию https://ru.yougile.com/api-v2. Разрешены только известные облачные домены YouGile по HTTPS, без редиректов с ключом. URL и ID из тела запроса не используются. Проверяются принадлежность доски проекту, колонок доске, размер ответа и предел пагинации. В ответ не попадают ключ или исходный текст ошибок API. Семь новых проверок используют только синтетические данные.

Нативное подключение YouGile в ChatGPT не предоставляет автоматически API-ключ серверу Mini App. После восстановления Supabase ключ настраивается владельцем непосредственно в Secrets, не в чате или GitHub. Фактические ID компании/досок и записи сотрудников не включены в тесты или конфигурацию репозитория.

## Правила до включения записи

Новые соответствует pending; для accepted отдельной колонки нет. В работе соответствует in_progress, На проверке — review, Готово — done. Входящее завершение не должно обходить проверку прав и контрольных точек CRM. Ожидает ответа не имеет отдельного текущего статуса CRM; для cancelled на доске нет колонки. Эти случаи нельзя молча превращать в другой статус или удаление.

Будущая синхронизация требует проверенных соответствий employee UUID ↔ YouGile user UUID и task UUID ↔ YouGile task UUID. Нельзя сопоставлять людей по имени или повышать роли. Нужны очередь, ограничение частоты, защита от дублей/циклов и правило разрешения конфликтов. Частная библиотека документов не передаётся без отдельного решения.

Официальный контракт проверен по https://ru.yougile.com/api-v2 и опубликованной там схеме https://ru.yougile.com/api-json : GET projects/{id}, boards/{id}, columns с boardId/limit/offset и paging.next. Создание задач имеет idempotencyKey, но на этом этапе не вызывается. Права API ограничены владельцем ключа: https://docs.yougile.com/docs/admin-guide-linux/api/ .
